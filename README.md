# Control Lab

Веб-система для построения структурных схем, моделирования линейных динамических систем и исследования систем автоматического управления.

Рабочий цикл:

`схема → проверка → матричная модель → расчёт → анализ → эксперимент`

Для короткой очной демонстрации выберите готовую схему `Демонстрация для защиты`.
Над рабочим полем появится компактный сценарий из трёх шагов: обычное моделирование,
оценивание состояния и LQG-управление по измеряемому выходу. После третьего шага можно
открыть печатную сводку эксперимента. Текст двухминутного объяснения находится в
[`docs/defense_demo.md`](docs/defense_demo.md).

## Возможности

- визуальный редактор блочных схем с обратными связями и подсистемами;
- единая модель схемы в пространстве состояний `x' = Ax + Bu`, `y = Cx + Du`;
- моделирование методами RK4 и `solve_ivp`;
- полюса, устойчивость, управляемость и наблюдаемость;
- временные и частотные характеристики;
- P-, PI-, PD- и PID-регуляторы, численная настройка PID;
- parameter sweep и Monte Carlo-анализ неопределённых параметров;
- эталонные численные эксперименты;
- сохранение проектов в JSON и SQLite;
- дискретный наблюдатель Люенбергера и стационарный фильтр Калмана с проверкой наблюдаемости, шумовым экспериментом и метриками ошибки;
- управление по измеряемому выходу: LQR с Люенбергером и LQG с проверкой принципа разделения, шумов и насыщения;
- обучение дешёвой нелинейной политики по демонстрациям ограниченного MPC с on-policy-агрегацией данных и Lyapunov-supervisor.

## Обучение регулятора

Раздел `Обучение` доступен прямо в верхней навигации и сам собирает матрицы текущей схемы — предварительный запуск обычного моделирования не требуется. Можно выбрать канал управления и наблюдаемый выход. Режим выполняет следующие шаги:

1. Непрерывная модель точно дискретизируется методом ZOH с выбранным шагом; управление вычисляется и прикладывается один раз на интервал дискретизации.
2. Конечногоризонтный MPC решает конденсированную box-QP и формирует пары `состояние → управление` с ограничением `|uₖ| ≤ umax`.
3. Нечётная нелинейная политика обучается ridge-регрессией. Её локальная часть фиксируется по линеаризации MPC, а обучается только нелинейный остаток с нулевой производной около `x=0`.
4. В нескольких on-policy-раундах ученик запускается самостоятельно, MPC повторно размечает посещённые состояния, и объединённая выборка переобучается. Это DAgger-подобное imitation learning, не reinforcement learning.
5. Политика проверяется на новых начальных состояниях и случайной отложенной выборке.
6. Lyapunov-supervisor проверяет фактически приложенное, уже ограниченное действие и при нарушении условия передаёт управление резервному LQR.
7. Для резервного LQR вычисляется область `Ωρ = {x: xᵀPx ≤ ρ}`, внутри которой ограничение `|u| ≤ umax` заведомо не нарушается.

Ограничение управления применяется одинаково к MPC, обученной политике, резервному LQR и комбинированному режиму. Результат содержит локальные линеаризации политик, ошибки до и после on-policy-агрегации, диагностический residual QP-решателя, долю активных ограничений, интегральную стоимость, стабилизацию, насыщения и вмешательства supervisor.

Локальная устойчивость этого режима проверяется в `z`-плоскости, а условие supervisor имеет дискретный вид `V(xₖ₊₁) − V(xₖ) ≤ −α·dt·||xₖ||²`. Последнее состояние горизонта не считается отдельным приложенным управляющим решением.

Ограничения режима:

- синтезируется внешний регулятор для всей собранной линейной модели; предпочтительна разомкнутая модель объекта;
- обучаемый регулятор пока использует истинный полный вектор состояния; реализованный отдельный наблюдатель ещё не включён в замкнутый контур обучения;
- MPC учитывает ограничение входа, но пока не содержит ограничений состояния и выхода;
- функция Ляпунова относится к номинальной линейной модели и подтверждает устойчивость, но не выполнение ограничений состояния;
- при конечном `umax` формальная гарантия резервного LQR локальна и действует только внутри вычисленной области `Ωρ`;
- вне `Ωρ` переключение на насыщенный резервный LQR является эвристическим восстановлением без формальной гарантии;
- безопасность относительно ограничений состояния требует отдельной barrier-функции (CBF);
- экспериментальная доля стабилизации не является формальным доказательством для всех начальных состояний.

## Наблюдатель состояния

Раздел `Наблюдатель` также доступен прямо в верхней навигации. Он автоматически собирает модель текущей схемы и сравнивает на одном шумовом эксперименте:

- наблюдатель Люенбергера с размещением полюсов `Ad − LC` в `z`-плоскости;
- стационарный дискретный фильтр Калмана, полученный из DARE для заданных `Q` и `R`.

Перед расчётом проверяется ранг матрицы наблюдаемости дискретной пары `(Ad, C)` для выбранного `Scope`. Интерфейс показывает истинные и оценённые состояния, норму ошибки, инновации, RMSE, спектральный радиус, усиление `L` и доверительную полосу `±3σ` Калмана. Шум процесса задаётся как стандартное отклонение на один дискретный шаг; вход считается известным наблюдателю.

## Управление по выходу и LQG

Раздел `LQG-контур` находится в верхней навигации и не требует предварительного моделирования. Выбранный `StepInput` трактуется как физический канал управления, а выбранный `Scope` — как единственное измерение. Модуль сравнивает три контура на одной реализации начального состояния и шумов:

- эталонный дискретный LQR, которому доступно истинное состояние;
- LQR с управлением `u = −Kx̂` по наблюдателю Люенбергера;
- LQG: тот же LQR с оценкой стационарного фильтра Калмана.

Для постоянного задания `r` во всех трёх контурах используется один статический
префильтр `N` и закон `u = −Kx̂ + Nr`. Он рассчитывается из установившегося режима
замкнутой дискретной модели и устраняет статическую ошибку номинального SISO-канала,
если требуемое управление не упирается в ограничение. Основные настройки находятся
на экране, а параметры синтеза и шумов свёрнуты в `Дополнительные настройки`.

Перед синтезом проверяются полные ранги дискретных пар `(Ad, Bd)` и `(Ad, C)`. Для ненасыщенной линейной модели явно строится объединённая динамика объекта и ошибки оценивания; её полюса сверяются с объединением полюсов LQR и наблюдателя. Все фактические траектории используют одинаковое ограничение `|u| ≤ umax`. Если насыщение активно, интерфейс сообщает, что линейный принцип разделения подтверждает только локальную устойчивость в ненасыщенной области. Префильтр не компенсирует постоянное внешнее возмущение и ошибку модели; для этого потребовалось бы интегральное состояние, которое намеренно не добавлено в интерфейс.

## API

- `GET /health` — состояние backend;
- `POST /validate` — проверка схемы;
- `POST /analyze` — сборка и анализ общей модели;
- `POST /simulate` — моделирование;
- `POST /tune/pid` — настройка PID;
- `POST /learn/safe-controller` — обучение и проверка регулятора;
- `POST /analyze/observer` — синтез и сравнение наблюдателей состояния;
- `POST /analyze/output-feedback` — сравнение LQR, Люенбергера и LQG;
- `GET /experiments/catalog`, `POST /experiments/run` — эталонные эксперименты;
- `/projects` — серверное хранение проектов.

## Запуск для разработки

Требуются Python 3.12 или новее, Node.js 18 или новее и npm.

Backend:

```bash
cd backend
python -m venv .venv
source .venv/bin/activate       # Linux/macOS
# .venv\Scripts\Activate.ps1   # Windows PowerShell
python -m pip install -e ".[dev]"
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Frontend:

```bash
cd frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

Либо через Docker:

```bash
docker compose up --build
```

## Границы проекта

Система предназначена для учебных и исследовательских расчётов. В ней нет DAE-решателя, совместного редактирования и аппаратного контура реального времени. Алгебраические петли без динамического звена отклоняются при проверке схемы.
