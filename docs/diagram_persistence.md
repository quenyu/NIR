# Сохранение и загрузка структурных схем

Проекты хранятся в двух видах:

* **на сервере (основной способ).** Кнопка сохранения в шапке или Ctrl+S. SQLite, `backend/app/storage/projects.py`:
  версия схемы БД в `PRAGMA user_version`, одно закрываемое соединение на операцию, оптимистическая блокировка
  по `version`. При конфликте API отвечает 409 `project_conflict`, и редактор предлагает открыть актуальную
  версию или сохранить копию. Сервер принимает только схему, которая собирается в модель.
* **в JSON-файле (импорт и экспорт).** Меню «⋯» → «Экспорт JSON» / «Импорт JSON». Формат описан ниже.

Положения блоков вложенных уровней хранятся в `Subsystem.parameters.layout` и записываются для всех открытых
уровней перед сохранением.

## Состав JSON-проекта

JSON-файл позволяет сохранить проект и позднее полностью восстановить:

- блоки и их параметры;
- входные и выходные порты;
- соединения между блоками;
- координаты блоков на рабочем поле;
- положение и масштаб рабочей области;
- выбранный решатель;
- значения `t_end` и `dt`.

## Формат файла

Текущая версия формата — `1`.

```json
{
  "format": "nir-dynamics-project",
  "version": 1,
  "metadata": {
    "title": "Структурная схема",
    "exported_at": "2026-07-07T12:00:00.000Z",
    "generator": "NIR Dynamics Web Prototype"
  },
  "diagram": {
    "blocks": [],
    "connections": []
  },
  "layout": {
    "positions": {},
    "viewport": {
      "x": 0,
      "y": 0,
      "zoom": 1
    }
  },
  "simulation": {
    "solver": "solve_ivp",
    "t_start": 0,
    "t_end": 6,
    "dt": 0.01
  }
}
```

## Проверка импортируемого файла

Перед заменой текущей схемы выполняется локальная проверка:

- JSON должен корректно разбираться;
- версия формата должна поддерживаться;
- идентификаторы блоков должны быть непустыми и уникальными;
- типы блоков должны входить в поддерживаемый набор;
- параметры должны соответствовать типу блока;
- порты должны соответствовать параметрам блока;
- связи не могут ссылаться на отсутствующие блоки и порты;
- один вход не может иметь несколько источников;
- координаты и параметры моделирования должны быть конечными числами;
- размер файла не должен превышать 5 МБ.

Если обнаружена ошибка, текущая схема не изменяется, а пользователь получает список причин.

Неполная схема допускается: например, блок может пока не иметь обязательного входного соединения. Математическая корректность такой схемы проверяется сервером при запуске моделирования.

## Совместимость

Импорт поддерживает:

1. новый проектный формат `nir-dynamics-project` версии 1;
2. старые JSON-файлы, содержащие только `blocks` и `connections`;
3. старые запросы моделирования, где схема находится в поле `diagram`.

Для старого формата координаты блоков создаются автоматически, а параметры моделирования получают значения по умолчанию. После следующего сохранения файл будет записан в новом формате.

## Реализация

Основной код расположен в:

```text
frontend/src/features/diagramPersistence.ts
```

Интеграция с редактором выполнена в:

```text
frontend/src/pages/MainPage.tsx
```

Автоматические тесты:

```text
frontend/tests/unit/run-persistence-tests.mjs
frontend/tests/e2e/persistence.spec.ts
```

Запуск быстрых unit-тестов:

```bash
cd frontend
npm run test:persistence
```

Запуск E2E-тестов после установки браузеров Playwright:

```bash
cd frontend
npx playwright install
npm run test:e2e
```
