## 3. Математические проблемы

| | Было | Итог | Проверка |
|---|---|---|---|
| M1 жордановы блоки на оси | 1/s², (s²+1)² → «marginal» | классификация по алгебраической и геометрической кратности | `test_stability_analysis.py` |
| M2 ранг Калмана | Butterworth n = 8 → ранг 7 | PBH на сбалансированной реализации | `test_stability_analysis.py`, исследование §4 |
| M3 показатели качества | `y∞` = последний отсчёт; t_рег у расходящегося сигнала | `y∞ = (D − CA⁻¹B)r` только для устойчивой системы | `test_quality_analysis.py` |
| M4 шаг RK4 | моды на мнимой оси не проверялись (|y| ~ 10¹³²) | проверка всех мод с Re ≤ 0, подсказка dt_max; растущие моды не блокируются | `test_stability_analysis.py`, e2e |
| M5 частоты | запасы по замкнутой ПФ; полюса на оси роняли `/simulate` | ЛАЧХ/ЛФЧХ/АФЧХ по каналам, без запасов; защищённые частоты | `test_frequency_analysis.py` |
| M6 разрывы | теоретически хрупкое сравнение `t0+h` (не воспроизводилось) | разрыв определяется по узлу сетки | `test_solvers.py` |
| M7 противоречивая устойчивость | поблочная и полная оценки расходились | одна устойчивость полной модели | e2e, `test_transfer_function.py` |
| M8 автонастройка PID | — | подсистема удалена | — |

Дополнительно:
* E1 — корректные алгебраические петли решаются;
* E2 — метки Scope с путём подсистемы;
* E3 — прямой проход порта;
* E5 — микрошаг в конце сетки;
* E7 — расположение блоков при сохранении изнутри подсистемы;
* E8 — смысл петли не выводится из рисунка.

E4 (начальные условия TF/PID) оставлено как ограничение.

## 4. Архитектурные проблемы

| | Итог |
|---|---|
| A1 SQLite | соединение закрывается всегда (тест на `ResourceWarning`; старый код оставлял 3 соединения на одно сохранение); `user_version` и миграция; 404/409/413/500/503 |
| A2 ошибки API | единый формат `{code, message, errors[]}`; в 4xx попадают только ошибки запроса, схемы и решателя |
| A3 повторная обработка | одна проверка и одно раскрытие на запрос |
| A4 дублирование математики | после удаления стендов по одной реализации каждого алгоритма |
| A5 клиент API | один `api/client.ts`; Pydantic-детали читаются, не-JSON ответы обрабатываются, 409 показывается |
| A6 статусы и коды | единый словарь статусов, коды диагностики по коду ответа сервера |
| A7 правила параметров | одна таблица в `features/blockParameters.ts`; Sum читается как на backend |
| A8 мёртвый код | удалён (+ 498 перекрытых CSS-объявлений) |
| A9 линтеры и e2e | ruff, ESLint, `noUnused*`; e2e на реальном backend |

## 6. Ограничения

* Только линейные непрерывные стационарные звенья, только ступенчатые источники.
* Начальные условия TF/PID нулевые; `y0` фильтра Баттерворта — состояние минимальной нормы, а не равновесие.
* Различные полюса на мнимой оси ближе `≈ 6·10⁻⁶·‖A‖` друг к другу считаются одним кратным полюсом
  (`docs/architecture_overview.md`, §8).
* Идентификаторы блоков не могут содержать `::` и начинаться с `@` (зарезервированы для путей и портов).
* Запасы устойчивости не вычисляются (нужно явное размыкание контура).
* Требования кафедры к оформлению ВКР в репозитории отсутствуют и согласуются отдельно.

## 7. Возможные направления развития (не входят в работу)

* Размыкание контура в выбранной точке → `L(s)`, запасы устойчивости.
* Parameter sweep пользовательской схемы.
* Источники sin и линейно нарастающего сигнала.
* Нелинейные и дискретные блоки.
